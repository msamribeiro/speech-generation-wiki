> [!abstract] arXiv · 2026 · Preprint
> **Tal Kozakov et al.** (Ben-Gurion University of the Negev) · [→ Paper](https://arxiv.org/abs/2609.12563) · Demo: ✓ · Code: ✗
>
> One direction-conditioned Transformer translates discrete tokens directly between three same-rate speech tokenizers (GLM-4-Voice, Mimi, DualCodec), so one model's tokens can be decoded by another model's decoder with no waveform decode and re-encode in between.

## Problem

Speech LMs and codec-based generators each use their own tokenizer, and the resulting token spaces differ in vocabulary size and codebook structure (single codebook vs. multi-codebook residual vector quantization). When two speech models must exchange content, as in a cascaded voice agent or a speech-to-speech translation pipeline, the usual bridge is to decode model A's tokens to a waveform and re-encode that waveform with model B's tokenizer. This "waveform bridging" adds two neural passes of latency and can lose information at each step. The paper asks whether a learned model can map one tokenizer's token sequence directly onto another's.

## Method

TokenMapper is a supervised token-to-token translator. Training pairs come from encoding the same utterance with each tokenizer, so the source sequence (C_A codebooks × T frames) and target sequence (C_B codebooks × T frames) align frame by frame. The formulation therefore requires a shared effective token rate; different or variable rates are left to future work (§2.1, Appendix F).

Each source token gets a learned embedding, summed with a positional embedding, a codebook-index embedding and a learned direction embedding that identifies the source→target pair (§2.2.1). A shared 4-layer Transformer encoder (hidden size 256, 8 heads) processes each codebook channel separately, with self-attention only along time (§2.2.2, Appendix A). A direction-specific routing function then shapes the encoder output for the target structure (§2.2.3–2.2.7):

- single → single: identity;
- multi → single: learned attention pooling across source codebooks;
- multi → multi: each target codebook receives the concatenation of the first source codebook stream (treated as a shared, more semantic base) and its corresponding source stream;
- single → multi: the single stream is broadcast to every target codebook.

Each target codebook has a one-layer Transformer output head and a linear projection to the target vocabulary. Training uses token-level cross-entropy summed over target codebooks and frames, with one encoder shared across all six directions and direction-specific heads (§2.3). Inference is a single non-autoregressive forward pass with argmax decoding; the predicted tokens are then decoded by the target tokenizer's own decoder. The parameter count is not reported.

The experiments cover all six ordered pairs among GLM-4-Voice (1 codebook), Mimi from Moshi (8 codebooks) and DualCodec (8 codebooks). Training uses 90% of the LibriSpeech training utterances (600 epochs, batch 32, Adam at 5e-4). Evaluation uses LibriSpeech test-clean and VCTK. WER comes from Whisper large-v3 transcripts and automatic quality from UTMOS-v2. A 32-listener MOS test covers 15 samples: two utterances per direction plus one native reconstruction per target tokenizer (§3, Appendix B).

## Key Results

On this page, the WER gap is translated WER minus the native reconstruction WER of the target tokenizer. A positive gap means translation is worse.

**Intelligibility (Tables 1–2).** On LibriSpeech, native reconstructions score 3.29–4.75% WER and translations score 5.85–9.98%, a gap of 2.56–5.96 points. GLM-4-Voice → DualCodec has the lowest translated WER (5.85% against 3.29% native DualCodec). DualCodec → Mimi has the highest (9.98% against 4.02% native Mimi). On VCTK the gap is 2.96–6.83 points: DualCodec → GLM-4-Voice has the smallest gap and Mimi → DualCodec the largest (9.18% against 2.35%).

**Perceptual quality (Tables 3–5).** On LibriSpeech, translated UTMOS ranges from 1.98 to 3.24, against 2.93–3.32 for native reconstructions. Translations into GLM-4-Voice nearly match it (3.24 and 3.16 against 3.27 native). Translations into Mimi drop the most (2.10 and 1.98 against 2.93). Human MOS shows the same pattern. Translations into GLM-4-Voice score 4.39 and 4.36 against 4.50 native, translations into DualCodec score 3.03 and 3.01 against 3.76 native, and DualCodec → Mimi scores 2.29 against 3.08 native. The MOS test is small: one native sample per target and two utterances per direction.

**Latency (Table 6).** The offline end-to-end transfer path is measured on an RTX 6000. Savings over waveform bridging depend strongly on the direction:

- 94.5% (972 ms) for GLM-4-Voice → DualCodec and 93.5% for GLM-4-Voice → Mimi;
- 87.4% for Mimi → DualCodec;
- only 4.8–10.4% for DualCodec → GLM-4-Voice, Mimi → GLM-4-Voice and DualCodec → Mimi.

The TokenMapper module itself takes 2.65–4.50 ms per utterance (Table 9).

**Ablations (Table 7, Table 10).** Removing direction conditioning raises WER from 9.31% to 57.62% (GLM-4-Voice → Mimi) and from 7.91% to 77.21% (Mimi → DualCodec). A single shared output head gives 83.01–96.75% WER, and a 4-layer MLP head gives 67.52–99.46%. Cross-codebook attention in the encoder raises WER to 18.86% and 22.83%, although its UTMOS for Mimi → GLM-4-Voice is marginally higher (3.26 against 3.24). Full-context concatenation for multi → multi raises WER to 26.79%. A local token-mapping baseline fails almost completely (97.6–100% WER).

**Adding a target (Appendix C, Table 8).** With the encoder frozen, training only new XY-Tokenizer heads for 30 epochs gives 6.23–8.95% WER against 3.03% for native XY reconstruction. The authors present this as preliminary.

The main comparison is fair as far as it goes, because every translation is scored against the native reconstruction of the same target tokenizer. However, the paper never reports WER, UTMOS or MOS for the waveform-bridging baseline itself. It measures bridging only for latency, so the claimed information loss of bridging is not quantified.

## Novelty Assessment

The architectural contribution is real but modest. Direct translation between heterogeneous codec token spaces is a new task framing. The direction-conditioned shared encoder with structure-specific routing (attention pooling, base-stream concatenation, broadcast) is a new design for it. Each building block (Transformer encoder, attention pooling, per-codebook heads, cross-entropy) is standard. The ablations support each design choice and show that simpler token-domain mappings fail. The scope is narrow: three tokenizers that share a frame rate, frame-aligned paired supervision, and English read speech. The motivating use cases (voice agents, speech-to-speech translation) are never tested; no downstream speech LM or translation system consumes the translated tokens.

## Field Significance

Moderate — the paper shows that independently trained speech tokenizers with very different codebook structures can be bridged in the token domain while staying within a few WER points of native reconstruction. It also shows that fine acoustic detail transfers much less reliably than content, especially into multi-codebook RVQ targets. It is a feasibility study for codec interoperability rather than a deployed component. The authors state that the paper is accepted to AACL-IJCNLP 2026 (Findings); this page summarizes the arXiv preprint.

## Claims

- **supports:** Discrete token spaces of independently trained speech tokenizers share enough structure that a learned direct mapping can preserve intelligibility without reconstructing the waveform.
  > *Evidence:* Across all six ordered pairs among GLM-4-Voice, Mimi and DualCodec, translated WER stays 2.56–5.96 points above native target reconstruction on LibriSpeech and 2.96–6.83 points above it on VCTK. This holds for single → multi, multi → single and multi → multi codebook mappings. *(§4.1, Tables 1–2)*
- **complicates:** Cross-tokenizer translation carries linguistic content more reliably than fine acoustic detail, and the quality loss is largest for multi-codebook residual-quantized targets.
  > *Evidence:* Translations into the single-codebook GLM-4-Voice nearly match native quality (UTMOS 3.24/3.16 against 3.27; MOS 4.39/4.36 against 4.50). Translations into Mimi drop to UTMOS 2.10/1.98 against 2.93, and DualCodec → Mimi falls to MOS 2.29 against 3.08 native. *(§4.2–4.3, Tables 3 and 5, Appendix G)*
- **refines:** Bypassing waveform bridging between speech models cuts transfer latency in proportion to how much of the bridge is spent on neural decoding and re-encoding, not uniformly.
  > *Evidence:* The token-domain path saves 94.5% (972 ms) for GLM-4-Voice → DualCodec and 93.5% for GLM-4-Voice → Mimi. It saves only 4.8–10.4% for DualCodec → GLM-4-Voice, Mimi → GLM-4-Voice and DualCodec → Mimi, where the authors describe source and target tokenizer runtimes as more balanced. *(§4.4, Table 6)*
- **supports:** Mapping between codec token spaces requires sequence-aware modelling that knows the source and target structure; local token correspondences are not sufficient.
  > *Evidence:* A local supervised token-mapping baseline gives 97.6–100% WER. Removing direction conditioning, sharing one output head, or using MLP heads raises WER from 7.91–9.31% to 33.52–99.46%. Mixing codebooks in the encoder raises WER to 18.86–22.83%. *(§5, Table 7; Appendix E, Table 10)*

## Limitations and Open Questions

> [!warning]
> The method covers only three tokenizers that share a frame rate, and it needs frame-aligned paired token data from encoding the same utterances with both tokenizers. The human MOS rests on two utterances per direction and one native sample per target. Waveform bridging is compared only on latency, never on WER or perceived quality.

- Rate-mismatched or variable-rate tokenizers would need a temporal alignment module. Appendix F only discusses options for it (resampling, monotonic attention, CTC alignment, duration adaptors).
- Training and evaluation use only English read speech (LibriSpeech, VCTK). The authors note that VCTK does not establish robustness to strong domain shift, such as music against speech tokenizers.
- No downstream system (a speech LM, a dialogue agent, a speech-to-speech translator) consumes the translated tokens, so the motivating use cases are untested.
- Latency is offline and per utterance. Streaming behaviour is not evaluated, and the frame-aligned non-autoregressive mapper would need adaptation for it.
- Paired data must be regenerated when a tokenizer version changes. Adding a new target through head-only adaptation is shown only as a preliminary test (Appendix C).
- Speaker similarity is not measured, so how well voice identity survives translation is unknown beyond the spectrogram inspection in Appendix G.
